# GP-01 — Project charter (draft v0.1)
**Prepared:** 2026-11-07  
**Status:** PRE-PRODUCTION — balanced quality + business goal approved; genre and concept still open.

## Mission
Create an original, polished, maintainable game using disciplined pre-production, transparent development evidence, and practical player feedback. The first playable release must be finished and enjoyable before feature expansion.

## Operating principles (agreed direction)
1. **Pre-production first.** We define audience, fun hypothesis, differentiator, scope, art style and measurable success before full production.
2. **Professional quality over haste.** Working gameplay, clear visual language and stable builds beat premature feature breadth.
3. **One source of truth.** Maintain living GDD, technical design, art bible, decisions, risks, tests and build manifests.
4. **Evidence-driven status.** Separate Designed, Implemented, Built, Tested, Approved, Released. Never collapse these into “done.”
5. **Small, testable increments.** The gameplay prototype validates fun; the vertical slice validates final-quality production; only then scale.
6. **Explicit change control.** New ideas must pass impact review before joining scope.
7. **Original and licensed content.** Track asset/source rights and third-party dependencies.
8. **Transparent limitations.** A no-local-install workflow is a goal pending remote build proof; it is not guaranteed by a plan.

## Product priority update — 2026-11-07
**APPROVED:** Creative quality and business viability are co-equal objectives. Professional genre/market discovery must NOT be mistaken for genre, title or visual style approval (DEC-009 and DEC-010).

## Scope baseline
**Known:** User requests a game built from scratch with comprehensive design/research and professional continuity. They prefer not to install a game engine locally; Android APK testing is an expected path from the conversation.  
**Proposed, not decided:** Android-first; free-first development pipeline; offline-single-player for a first game; Godot as engine candidate; initial tight vertical slice.  
**Not decided:** Game idea, audience, genre, dimension (2D/3D), controls, player session length, monetization, art direction, distribution, budget ceiling, release date, brand/name, analytics and accessibility specifics.

## Business and experience objectives (to set during discovery)
- **Player promise:** One sentence: “For [audience], this game delivers [specific emotion/activity] through [unique mechanic].”
- **Fun hypothesis:** What exactly should be enjoyable by minute 1 and by session 3?
- **Minimum lovable release:** A complete, coherent experience with accessible onboarding, no broken critical paths, original visual identity, reliable saves where applicable, and honest monetization.
- **Viability hypothesis:** Clear audience and discovery path, realistic content cost, sustainable support burden.
- **Targets:** Establish measurable targets after genre selection; do not invent retention, revenue or download forecasts.

## Key responsibilities
- **Assistant / Creative & Engineering Lead:** research, architecture, implementation, visual-system proposals, test matrices, documentation, issue triage, build verification.
- **User / Product Owner:** approves concept, brand, artistic direction, priorities, major scope changes and release acceptance; tests on owned devices where practical.

## Non-goals for P0
No gameplay coding, no package name, no unreviewed characters, no art-style lock, no payments/ads integration, no launch date, and no claimed APK.

## Phase 0 exit checklist
- [ ] Product brief approved
- [ ] Three or more candidate game concepts documented with scored assumptions
- [ ] Target audience and platform confirmed
- [ ] Game's primary fun hypothesis and key differentiator stated
- [ ] First-release scope and non-goals bounded
- [ ] Rough cost/time/asset feasibility assessment recorded
- [ ] Critical Android export/publishing risks assigned
- [ ] Product owner approves which concept enters GDD development
