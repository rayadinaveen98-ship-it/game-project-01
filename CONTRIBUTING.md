# Contributing to Game Project 01

## Work process
1. Define a bounded change and measurable acceptance criteria.
2. Work on a branch named `docs/<topic>`, `feature/<topic>`, `fix/<topic>`, or `experiment/<topic>`.
3. Reference related decision, risk, or issue identifiers.
4. Validate and document the work. Never call a draft an approved design.
5. Submit for review before merging to `main`.

## Quality requirements
- Every art asset records source/license and design-system consistency.
- Every gameplay change has a reproducible test or playtest protocol.
- Every release artifact must have a version, build log, digest, and test notes.
- Never commit secrets, signing keys, access tokens or unlicensed assets.
- Do not publish strategic concept/IP documents while the repository is public.

## Commit style
`docs: ...`, `feat: ...`, `fix: ...`, `test: ...`, `chore: ...`.

## Change control
Significant design deviations require a decision-log update: what changed, why, impact, approval and resulting scope.
