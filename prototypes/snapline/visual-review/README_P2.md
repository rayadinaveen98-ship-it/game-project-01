# Snapline Sprint — P2 Visual Direction Lab

**Status:** THREE PROPOSED DIRECTIONS; OWNER SELECTION PENDING. Not production artwork.

This design lab extends the verified P1 browser mechanics without altering course coordinates, collision or route simulation. It exposes three CSS/Canvas theme configurations with the same physical detour course and the same Home / Game / Result UX.

## Open the prototype

- Open `standalone.html` in a browser. It includes all app source and styling without a network connection.
- Choose **A: Pulse Grid**, **B: Ink Trail**, or **C: Micro Runner** in the visual review rail.
- Choose **Home**, **Game**, or **Result** to inspect proposed screens. Home and Result are illustrative design states, not gameplay completion metrics.
- On **Game**, draw from `S` to `F`, select a course, press **RUN**. The P1 gameplay logic remains functional.

## The three directions

1. **A — Pulse Grid:** dark midnight foundation, luminous turquoise lines, coral obstacle edges, compact technical typography. High-contrast premium motion design. Risk: overly familiar cyber/neon arcade treatment.
2. **B — Ink Trail:** warm paper, visible restrained grain, evergreen pen line, terracotta hand-crafted blocks, serif display accent and subtle hand-drawn decorations. Risk: warmth comes at the cost of clarity if textures are amplified.
3. **C — Micro Runner:** soft lilac environment, toy-like pink barriers, confident indigo path, dimensional highlights and rounded UI. Risk: lively aesthetic could undermine precision if hitboxes or glow get too loose.

## Real implementation parity

- All three themes draw `Course.detour` with identical `start`, `finish`, `walls` and simulation code.
- Stroke centerlines and obstacle collision regions are unchanged by artwork.
- Theme palettes are implemented in `style.css` (UI) and `src/ui/render.ts` (Canvas).
- The three screenshots per option were generated by Chromium from this actual HTML/Canvas UI, with a *real* valid drawn route in Gameplay view (747/850 ink).
- Home/Result previews are simulated design presentations. A real game win appears via existing P1 result status, but does not automatically navigate into the proposed full-screen Result presentation.
